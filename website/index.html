Why Ratchet Exists

The "Looks Good To Me" Trap in AI Code Generation

When agents run unsupervised, they optimize for compilation and test evasion. Ratchet enforces a mechanical gate that cannot slip backward.

Without Ratchet (Unverified)

The AI Agent Declares Victory Early

  • ✕ Compilation ≠ Working UI: Code compiles with zero TypeScript errors, but the promo discount handler doesn't calculate the total.
  • ✕ Trivial Test Shortcuts: The agent writes a 2-line test that checks if the HTML title loaded and marks the entire task as "PROVEN".
  • ✕ Context Bloat & Log Dumping: Raw browser logs, HTML dumps, and traces overwhelm the agent's context window with thousands of tokens.
  • ✕ Broken Code Pushed to Git: No barrier stops the agent from committing and pushing broken user experiences directly to main.
With Ratchet (Verified Closed Loop)

Autonomous Mechanical Lock Gate

  • ✓ Binding Kane Acceptance Scenarios: ratchet sync maps 100% of plain-English PRD bullet points to executable browser tests.
  • ✓ Real Chrome Automation: Kane CLI types promo codes, clicks buttons, and verifies DOM state in real Google Chrome.
  • ✓ Surgical Repair Packets: Failures emit token-efficient JSON with exact memoryDiffs (Expected: $80, Got: $100) so agents fix bugs immediately.
  • ✓ Pre-Push Lock: .git/hooks/pre-push physically blocks git push until every single acceptance criterion passes.

Architecture

The 4 Mechanical Clicks of Ratchet

A deterministic pipeline designed for autonomous coding agents and human developer workflows alike.

01 / SPEC

PRD.md

Write user-observable requirements in plain English. Specify base prices, promo codes, and expected banner strings.

demo-app/PRD.md
02 / COMPILE

ratchet sync

Kane CLI ingests requirements and designs binding acceptance scenarios (_test.md) mapped 1:1 to criteria.

ratchet sync --prd PRD.md
03 / EXECUTE

ratchet verify

Kane CLI drives Google Chrome, collects step assertions, and returns a surgical RepairPacket on failure.

ratchet verify --json
04 / ENFORCE

ratchet hook

Installs a Git pre-push hook. Blocks pushes whenever verification fails; unlocks only when all criteria pass.

.git/hooks/pre-push
